Why it's hard

Manuals keep their facts where software reads worst

Warning
A wrong torque value or a dropped warning is worse than no answer. Every answer has to show its page.
Caution
Tables, numbered steps and warning boxes are exactly what plain PDF text extraction scrambles.
Notice
Public leaderboards rank parsers on other people's documents. They can't tell you how yours will fare.
From manuals to knowledge

Seven steps, each one measured

The bench scores every step separately, so a bad answer can be traced to the step that caused it.

  1. Parse

    A layout-aware parser turns each page into text and tables. Seven parsers compared; Docling led on manuals.

  2. Chunk

    Pages are cut into passages that never cross a page, so each one keeps its page number and heading.

  3. Search

    Keyword and embedding search run side by side and their rankings are fused.

  4. Rerank

    A small local model re-reads the top 30 passages against the question and re-orders them.

  5. Answer

    Claude answers from five passages only and cites them, or replies "not found".

  6. Grade

    Jev grades each answer with a confidence. Uncertain grades go to Claude for a second opinion.

  7. Label

    People add harder questions in the workbench, and the test set grows with use.

What it doesn't prove yet

Read this before you rely on it

Caution
The results come from nine public manuals and 168 questions. They show the method works, not how it performs on your manuals.
Caution
No person has checked the graders or the knowledge graph yet. Both have review tools ready in the workbench.
Notice
With four HVAC manuals the knowledge graph did not improve search over plain text. Its value so far is navigation; the search benefit is untested at scale.
